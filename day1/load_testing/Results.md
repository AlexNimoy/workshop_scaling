# Выводы

На основе анализа логов нагрузочного тестирования были получены следующие ключевые выводы:

## Производительность Async vs Sync (задержка 2 секунды)

- Async (Puma): ~22 транзакции/сек, 100% доступность, время ответа ~2017 мс
- Sync (Puma): всего 0.4 транзакции/сек при 30 пользователях, при большей нагрузке — 0 транзакций
  Вывод: Асинхронный режим значительно превосходит синхронный при IO-нагрузке

## Сравнение серверов (Async, задержка 2 секунды):

- Puma: ~22 транзакции/сек (50 пользователей), 100% доступность
- Thin: ~13 транзакций/сек (50 пользователей), 100% доступность
- Passenger: не справился с нагрузкой (0% доступность при 40+ пользователях)

## Производительность при нулевой задержке

- Sync_sleep_0: ~8200 транзакций/сек, отличная масштабируемость, время ответа 3–6 мс
  Показывает, что без IO-блокировок даже синхронная обработка даёт высокую пропускную способность

## Наблюдения по масштабируемости

- Асинхронные системы масштабируются линейно с ростом числа пользователей
- Синхронные системы с IO-нагрузкой полностью выходят из строя под нагрузкой
- Passenger показал плохую производительность при IO-нагрузке

## Анализ ключевых метрик

- Время ответа: асинхронный подход сохраняет стабильное время, близкое к задержке
- Доступность: критично отличается между подходами
- Скорость транзакций: напрямую зависит от модели обработки

Заключение: Асинхронная обработка критически важна для IO-нагруженных операций, особенно в условиях высокой конкуренции.
